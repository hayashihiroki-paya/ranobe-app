ライトノベルと読者を、“好きな要素”でつなぎなおす推薦・コミュニティサービス。

---

## サービス概要

作品を「ジャンル」ではなく「要素単位」で分析し、  
ユーザーの好みに合った作品を高精度でレコメンドするサービスです。

「読む前に、自分に合う作品かわかる体験」を目指して開発しました。

---

## 背景・課題

自身が累計1000冊近くライトノベルを読んできたヘビーユーザーであり、  
新しい作品との出会いに大きな課題を感じていました。

ライトノベルは、漫画・アニメと比較して作品情報が整理されておらず、

- ジャンル検索
- あらすじ確認
- レビュー確認

などを繰り返しながら探す必要があります。

しかし実際には、

- 「読んでみるまで自分に合うかわからない」
- 「好みの細かな要素で探しづらい」

という問題がありました。

そこで、

「ユーザーの好きな要素から作品を逆算して探せる仕組み」

を作りたいと考え、本サービスを制作しました。

---

## 主な機能

### 要素ベースの高精度レコメンド

お気に入り作品や好きな要素を登録することで、  
要素単位で類似性を分析し、ユーザーに合った作品を推薦します。

### ユーザー間の嗜好マッチング

嗜好一致度の高いユーザーを可視化し、  
そのユーザーのお気に入り作品から新たな作品との出会いを提供します。

---

## レコメンドロジック

単純なタグ入力数ベースの設計では、人気作品へ偏りやすい問題があるため、  
「入力傾向の近さ」を重視した設計にしています。

作品・ユーザー情報をベクトル化し、  
ベクトル同士の角度から類似度を測定する「コサイン類似度」を採用しています。

## 工夫した点

タグを細分化すると精度は向上しますが、  
一方で入力コストが増加し、離脱につながる課題があります。

そのため、

- タグ入力UIの簡略化
- 少ない入力でも推薦精度を維持できる設計

を重視しました。

具体的には、作品ごとに入力数の多いタグを「基礎タグ」として内部的に補完し、  
お気に入り登録だけでも一定の推薦精度が出るよう設計しています。

## ローカル開発環境

### 前提

- Node.js 20.9以上
- npm

### セットアップ

~~~bash
git clone https://github.com/hayashihiroki-paya/ranobe-app.git
cd ranobe-app
npm ci
cp .env.example .env
~~~

PowerShellでは、環境ファイルのコピーに `Copy-Item .env.example .env` を使います。`npm ci` の完了時にPrisma Clientが生成されます。

### 環境変数

開発用の値を `.env` に設定します。実データを含む本番DBの接続先や秘密値は使わず、Gitへコミットしないでください。

- `DATABASE_URL`: 開発用PostgreSQL/Neonの接続文字列
- `NEXTAUTH_URL`: ローカルでは `http://localhost:3000`
- `NEXTAUTH_SECRET`: ローカル用のランダムな秘密値
- `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`: Googleログインを使う場合に設定
- `RAKUTEN_APP_ID`: 楽天APIを使う場合に設定
- `ADMIN_EMAIL`: 管理者向けAPIを使う場合に設定

楽天APIは現在の `main` が旧接続方式のままです。Issue #12 の移行が統合された後は、移行後の `.env.example` に追加される `RAKUTEN_ACCESS_KEY` も設定してください。新認証方式での実接続確認はIssue #12で管理しています。

### データベースと起動

開発用DBであることを確認してからマイグレーションを適用し、アプリを起動します。

~~~bash
npx prisma migrate deploy
npm run db:seed
npm run dev
~~~

ブラウザーで `http://localhost:3000` を開きます。Googleログインを確認する場合は、Google OAuth側にもローカルのコールバックURLを登録してください。

### チェック

~~~bash
npm run lint
npm test
~~~

### 初期データ

`npm run db:seed` はタグとカテゴリ重みの初期データをupsertする、再実行可能なコマンドです。開発用DBであることを確認してから実行してください。`prisma/seed.ts` は30件のデモユーザーと関連データを作成し、標準コマンドには含めていません。詳しい前提は [作業計画](docs/PROJECT_WORK_PLAN.md) を参照してください。
